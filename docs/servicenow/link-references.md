# 单元格引用常用链接（设计方案）

表格单元格可以不直接填 URL，而是引用「常用链接」里收藏的某一条。本文档记录设计方案（由 Opus 4.8 给出）和最终实现时的取舍。

## 背景

- 「常用链接」是按用户保存的收藏列表，每条 `{id, name, url, note}`，存在用户设置 `servicenow_links` 中，接口为 `GET/POST /api/servicenow/links`。
- 表格单元格保存在 `table.cells`，键为 `"<行>,<列>"`，值原本只能是 ServiceNow 列表 URL。
- 刷新时把单元格 URL 发给 `/api/servicenow/run/stream`，由 `servicenow_worker.py` 读取记录数。

## 1. 可行性与 v1 范围

可行，改动集中在前端。单元格本来就存字符串，刷新链路上已经有 `_is_servicenow_url` 的校验。只要在前端把「引用」解析成真实 URL 再进入这条链路，worker 和后端都不用改。

v1 范围：

- 只支持引用**单个**常用链接。
- 不做多个链接的组合（例如 filter 取交集）。worker 只会 `parse_list_url` 解析单个列表 URL，组合需要在 query 层拼接条件，复杂且容易出错，留给后续版本。
- 录入体验像 Excel：输入 `=` 选链接；内部按 id 存储。

## 2. 数据模型

单元格的值有三种形态，靠前缀区分，天然向后兼容：

| 值 | 含义 |
|----|------|
| `https://…` | 旧的纯 URL，行为不变 |
| `ref:<linkId>` | 引用常用链接，`<linkId>` 是 `SnLink.id` |
| 空字符串 | 空单元格 |

- **按 id 引用、按名称显示**：链接改名后，引用它的单元格自动跟随，无需迁移；重名也不会产生歧义。
- 不需要数据迁移。`save_config` 不校验单元格内容，`ref:` 字符串可原样保存。

## 3. 解析

在前端解析，紧贴刷新逻辑：`resolveCell(raw)` 用常用链接列表把 `ref:<id>` 展开成 URL。

- 刷新用的 URL 列表 `tableUrls` 取解析后的 URL 并去重。
- 解析后的 URL 仍然经过前端 `urlProblem()` 和后端 `_is_servicenow_url` 两道校验，worker 收到的永远是 `*.service-now.com` 的链接。
- `counts.values` 仍然以**真实 URL** 为键，所以计数、合计、复制结果只需要先解析再查表。

边界情况：

| 情况 | 处理 |
|------|------|
| 引用的链接已被删除 | 单元格显示「⚠ 引用的常用链接已删除」，刷新时跳过，合计按"数据缺失"处理 |
| 链接被改名 | id 不变，显示名自动更新 |
| 重名 | 靠 id 区分；下拉项显示备注辅助区分 |
| 常用链接还没加载完 | 单元格显示 `…`，刷新被拦下并提示稍后再试，避免发出未解析的引用 |
| 常用链接加载失败 | 单元格提示「无法加载常用链接」 |
| 点击数字跳转 | 用解析后的 URL；解析不了就不渲染成链接 |
| 复制结果 | 只用计数文本，不受影响 |

## 4. 编辑界面

- 单元格仍是一个输入框：输入 `=` 弹出常用链接下拉（按名称、备注过滤，回车选第一项）；旁边有 🔖 按钮，不想记语法时用它直接选。
- 选中后存 `ref:<id>`，单元格显示为带名称的标签，可点 ✕ 清除。
- 直接粘贴 `https://…` 的旧方式继续可用。
- 单元格里只输入了 `=…` 但没选择时，标红并提示「请从列表中选择一个常用链接」。
- 非编辑状态下，引用单元格和普通单元格外观一致，不增加杂乱。
- **跨组件数据共享**：抽成共享 hook `useSnLinks`，在 `ServiceNowTables` 中创建一份，再传给常用链接面板，避免重复请求，也保证面板里的改名、删除能立刻反映到单元格。

## 5. 后端改动

基本不需要。`run_stream`、`_is_servicenow_url`、`_stream_worker`、`save_config` 保持原样。

可选加固：在 `save_config` 对单元格值做宽松校验（只允许 `https://` 或 `^ref:[A-Za-z0-9_-]{1,36}$`）。v1 未做。

## 6. 实现对应关系

| 文件 | 内容 |
|------|------|
| `frontend/src/useSnLinks.js` | 共享 hook：加载、保存常用链接；导出 `REF_PREFIX` |
| `frontend/src/LinkCellInput.jsx` | 编辑态单元格输入：`=` 自动补全、🔖 选择、引用标签 |
| `frontend/src/ServiceNowLinks.jsx` | 常用链接面板，改为使用共享数据；删除时提示被引用的单元格数量 |
| `frontend/src/ServiceNowTables.jsx` | `resolveCell` / `cellProblem` / `linkUsage`；`cellInfo`、`tableUrls`、`refresh` 改为先解析引用 |
| `frontend/src/ServiceNowTables.css` | 引用标签与下拉样式 |

## 7. 决策记录

三个需要拍板的问题，采用的都是方案推荐的默认值：

1. **存储语法**：`ref:<id>`（改名安全），而不是直接存 `=名称`（直观，但改名或重名会断）。
2. **多链接组合**：v1 不做，只支持单个引用。
3. **刷新时遇到已删除或无法解析的引用**：跳过并在单元格标记，同时提示「已跳过格式不正确或已失效的链接」，而不是阻止整次刷新。

## 8. 公式（第二阶段）

在单元格里可以写公式，对多个常用链接的记录数做加法。

- **缩写**：每个常用链接有一个可选的 `alias`，由用户设置。规则：字母、数字、下划线，不以数字开头，最长 20 位，同一用户下不区分大小写、不能重复（前端和 `save_links` 都会校验）。
- **写法**：以 `=` 开头，用方括号引用缩写，例如 `=[PB]+[PR]`、`=([PB]+[PR])+3`。
- **语法**：`expr := term ('+' term)*`，`term := 整数 | [缩写] | (expr)`。只支持加法、括号、整数。解析器在 `frontend/src/formula.js` 中手写，不使用 `eval`。
- **刷新**：把所有公式用到的链接收集、去重，和其他单元格的链接一起发给 worker；结果在前端相加，后端和 worker 不用改。
- **显示**：单元格显示结果，悬停显示公式和各变量的值，公式单元格不做点击跳转。
- **错误**：缩写不存在、语法错误、括号不匹配等，单元格标红并给出提示。
- **数据不全**：某个变量没有数据时，按 0 计算并显示 `N ⚠`；该单元格参与合计时按"缺数据"处理，复制结果时留空，规则同现有合计。
- **输入**：输入 `[` 弹出带缩写的下拉；🔖 按钮在公式里会追加 `[缩写]`，在非公式单元格里则整格引用某个链接（`ref:<id>`）。
- **缩写被改名或删除**：先提示有几个单元格在使用；修改或删除后，依赖它的公式会报错，不会自动改写。
