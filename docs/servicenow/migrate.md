# 迁移：导出与导入配置

把统计表、常用链接、条件库导出成一个 JSON 文件，在另一台电脑上导入。入口是表格页标签栏里的「⇅ 迁移」。

## 导出内容

| 分组 | 内容 |
|---|---|
| 统计表 | 所有表格：标题、行列、单元格（URL / `ref:<链接 id>` / 公式）、合计 |
| 常用链接 | 名称、URL、备注、缩写 |
| 条件库 | 条件、条件名称、每张表对应的 host / app_path、从 ServiceNow 读到的字段和值名称 |

不导出：登录身份和 Edge 登录状态、刷新得到的数字（都是本机数据）。文件里没有任何凭据。

文件格式：`{ "format": "servicenow-migrate", "version": 1, "exported_at": ..., "tables": [...], "links": [...], "conditions": {...} }`，没选的分组不会出现。

## 导入

两种打开方式，没有常驻的拖拽区：

1. 「⇅ 迁移 → 导入配置…」，在对话框里拖入文件或点击选择。
2. 直接把 `.json` 文件拖到页面上，页面自动弹出导入对话框，松手即可（整个遮罩都能接收）。

读入文件后先**预览**（`POST /migrate/preview`，不写库），可以勾选要导入的分组，并选择：

- **合并到现有配置**（默认）
- **替换本机配置**（适合新电脑）：替换前会二次确认，并自动下载一份本机配置的备份 `servicenow-backup-*.json`。

点「导入」才真正写入（`POST /migrate/import`，后端会重新校验）。

## 合并规则

| 对象 | 规则 |
|---|---|
| 统计表 | id 重新生成；同名则重命名为「xxx（导入）」 |
| 常用链接 | 以 URL 去重，相同 URL 复用本机链接（本机没有缩写时补上）；新链接的缩写与本机冲突时加数字后缀（`PR` → `PR2`）；非 `https://*.service-now.com` 的链接被跳过；上限 200 条 |
| 引用重映射 | 导入表格里的 `ref:<旧 id>` 改写成本机链接 id；公式里被改名的 `[缩写]` 同步改写。找不到对应链接的引用会计入预览里的「失效引用」 |
| 条件库 | 以 (表, 条件) 去重，只增不删；条件名称、表来源、值名称以本机已有的为准，只补缺的 |
| 无效数据 | 越界的单元格、格式不对的合计、无效条件被丢弃，数量显示在预览里 |

替换模式下，如果某个分组里的有效项一个都没有（例如所有链接都被拒绝），该分组不会被替换，避免清空本机数据。

## 代码位置

- 后端：`app/routers/servicenow/migrate.py`，合并逻辑 `_merge` 是纯函数，测试见根目录 `test_sn_migrate.py`。
- 前端：`frontend/src/ServiceNowMigrate.jsx`（对话框和拖拽），入口与全页拖拽监听在 `ServiceNowTables.jsx`。导入后重新加载表格配置和链接，并重新挂载链接面板。
